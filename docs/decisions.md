## Repository and release

### One repository; each commit is one release of both halves

- **Why:**
  - the web app and the API change together;
  - one commit can be tested and deployed as a unit;
  - one rollback point covers both.
- **Evidence:**
  - [CLAUDE.md](../CLAUDE.md), "What this repo is";
  - the frontend was imported with its history in `85b7abb` (2026-09-24);
  - one deploy command arrived in `1b40e0f`.
- **Cost:** a deploy always ships all of `main`, so nobody may deploy while someone else's pushed work is untested.

### One contract, generated, and changes to `/v1` are additive

- **Why:** the web app, and later native apps, must never break silently.
- **Evidence:**
  - `docs/openapi.json` is generated by `backend/scripts/export_openapi.py`, and `--check` runs in `bun run build`
    and CI;
  - `routes.test.ts` fails when a proxied route or field disappears;
  - [api-contract.md](api-contract.md), "Compatibility".
- **Cost:** a breaking change needs a new endpoint or version, kept while old clients need the old one.

### CI is advisory

- **Why:** a release shouldn't wait on, or depend on, GitHub's runners.
- **Evidence:**
  - `d1bdf9f` (2026-09-28): "GitHub Actions is no longer a deploy dependency";
  - the headers of `deploy/deploy.sh` and `deploy/ci-gate.mjs`;
  - `bun run status` shows CI's verdict.
- **Cost:** a red CI job doesn't stop a deploy, so it has to be read ([testing.md, "Known baseline"](testing.md#known-baseline)).

## Architecture

### Web-first, not web-only (owner's rule)

- **Why:** the web app is the first client of a platform that should later serve iOS, Android, tablet and desktop
  apps without a rewrite.
- **Evidence:** [CLAUDE.md](../CLAUDE.md), "Architecture guardrail"; [architecture.md](architecture.md),
  "Clients".
- **The decisions it leads to:**
  - durable data and rules live in the API;
  - user preferences live in `/v1/me/settings`, not in browser storage;
  - authorisation is per user, in the API.
- **Cost:** no work on other clients or cross-platform abstractions until they're needed.

### PostgreSQL 16 + pgvector is the only datastore

- **Why:**
  - one system to secure, back up and restore;
  - chats, settings, progress, files and vectors share transactions.
- **Evidence:**
  - `68ebd27` (schema with pgvector, 2026-09-23);
  - `tests/test_architecture_guards.py` forbids GraphRAG, Chroma, Pinecone, Weaviate and Qdrant.
- **Cost:** vector search scales with one PostgreSQL. The embedding dimension (1536) is fixed in three places, and
  changing it needs a migration and a re-ingest.

### The browser talks only to the web app (the BFF)

- **Why:**
  - the session token stays in an httpOnly cookie, so script injection in a page can't read it;
  - the API has no public address;
  - the proxy is an allowlist, not a pipe.
- **Evidence:**
  - `frontend/apps/app/src/lib/server/proxy-core.ts` (allowlist, Origin check, 64 KB, unbuffered SSE, abort on
    leave);
  - `lib/api/routes.ts`.
- **Cost:**
  - every route the browser needs must be added to `routes.ts`;
  - a future native app will need a published API ([architecture.md](architecture.md), "Clients").

### One model call per turn, and the fallback only before the first token

- **Why:**
  - predictable cost and time;
  - a reply never mixes two models' words.
- **Evidence:**
  - [CLAUDE.md](../CLAUDE.md), "Backend internals";
  - `FallbackProvider` in `app/llm/`;
  - the LangGraph graph has no retries (`app/rag/graph.py`).
- **Cost:** if the provider fails mid-reply, that reply ends with an error. The student can regenerate it.

### asyncpg, on purpose

- **Why:** psycopg's async mode fails on Windows' Proactor event loop, which is where the owner develops.
- **Evidence:** [CLAUDE.md](../CLAUDE.md), "Cross-cutting".

### The web app runs on Node, not Bun's runtime

- **Why:** Bun doesn't signal a client disconnect, and Stop-on-leave depends on it.
- **Evidence:** `.node-version` (24.19.0) and [CLAUDE.md](../CLAUDE.md), "Pinned runtimes". Bun stays the package
  manager and task runner.

## Identity and security

### Sign-in on Better Auth in the web app; the API checks every request

- **Why:**
  - mature sign-in features without writing them: email codes, passwords, Google, two-step sign-in, CAPTCHA, the
    breached-password check;
  - the API still checks every request on its own.
- **Evidence:**
  - `6be7ce8` (2026-10-01) and `d32d492` (2026-10-02, two-step sign-in, CAPTCHA, breached passwords);
  - migration 0012 gives Better Auth its own role, `aichat_auth`, limited to the identity tables;
  - the API finds a session by its token's SHA-256.
- **Cost:** identity spans two processes. They share `AUTH_INTERNAL_TOKEN` for the API's loopback
  `/internal/auth/*`.

### Another student's data answers 404, never 403

- **Why:** the API never says whether an id exists.
- **Evidence:** `tests/test_authorization.py`; `NotFound` in `app/errors.py`.

### Every route needs a session, unless the owner made it public

- **Evidence:** `tests/test_route_auth.py` reads every route from the app's own OpenAPI description. A public
  route must be in its `PUBLIC` table with a reason. There are four public routes:
  - `/health` and `/ready`;
  - the academic catalogue;
  - email unsubscribe.

### One error envelope, and the backend's wording never reaches the page

- **Why:** stable codes for every client, and no internal detail leaks.
- **Evidence:** `app/errors.py` (`{"error": {code, message, requestId}}`); `proxy-core.ts`, "ERRORS". The web app
  has its own text for each code.

### Logs never contain message or document text, or keys

- **Evidence:** [CLAUDE.md](../CLAUDE.md), "Cross-cutting";
  `tests/test_chat.py::test_logs_never_contain_the_question_or_document_text`.
- **Cost:** a problem is debugged from ids, codes and timings, not from content.

## AI and learning

### Tests come from the question bank, never from the model

- **Why:** a question, its answer and its marking must be correct. A model can be wrong about any of them.
- **Evidence:**
  - `86392b1` (2026-10-16);
  - `app/qbank/chat_tests.py`: the tutor names a chapter, the server sets stored questions and
    `app/assessments` marks them.
- **Cost:** tests exist only for what the bank covers.

### Textbook search through the NCERT Knowledge Service's API only

- **Why:**
  - that service has its own data (about 19 GB on 2026-10-15), its own releases and its own repository;
  - PadhAI never reads its tables.
- **Evidence:**
  - `3671a4f` (2026-10-14);
  - `app/rag/ncert.py`: Classes 6–12 only, a query of at most 32 words.
- **Cost:** a network dependency, capped by `NCERT_KB_TIMEOUT_S`. Answers go on without it.

### Retrieval never fails a turn

- **Evidence:** [CLAUDE.md](../CLAUDE.md), "Backend internals"; the reason codes in `app/rag/graph.py`.
- **Cost:** an answer without sources is possible. The reason is in the log and in `messages.metadata`.

### JEV classifiers are extra, short and safe to lose

- **Why:** the intent router and the study scope filter shape answers, but they must never slow down or fail one.
- **Evidence:**
  - `391d732` (2026-10-22);
  - `INTENT_ROUTER` and `STUDY_SCOPE` are off by default, and capped by `INTENT_ROUTER_TIMEOUT_S`;
  - they are never retried.
- **Production (as reported, 2026-10-26):** both are on; the router's time cap is 5 s there (owner's decision,
  2026-10-23).

### Chat titles without a model

- **Why:** no second model call per chat.
- **Evidence:** `app/chat/titles.py`, "Deterministic and model-free". The title comes from the question's shape,
  the reply's first real heading, or the question's first words.

### Learning days follow India time

- **Why:** one clear day boundary for the streak, the countdown and "today", for the students PadhAI serves.
- **Evidence:** `app/progress/learning.py`; `DEFAULT_TIMEZONE=Asia/Kolkata`; Settings says "Days follow India
  time".
- **Cost:** a student elsewhere sees the day end at India's midnight.

### Voice is English only

- **Why:** OllaLink's speech has no Hindi.
- **Evidence:** `app/voice/`: voice is offered only when the tutor's language is English or unset.

## Data and files

### Untrusted files are parsed only in a sandbox

- **Why:** a crafted file must not be able to reach the API's process, secrets or network.
- **Evidence:**
  - `app/files/processing.py`: in production, a systemd transient unit with no network, no secrets, read-only
    files, and its own memory and time limits;
  - the API process never imports a parser.
- **Cost:** reading images needs Tesseract on the host, and production needs systemd.

### Files' bytes live in PostgreSQL

- **Why:** one datastore and one backup ([CLAUDE.md](../CLAUDE.md), "Files").
- **Evidence:** the `user_file_blobs` table; 100 MB per student.
- **Cost:** the database grows with uploads. Uploads stop when PadhAI's own tables reach 3 GiB or the disk has
  less than 5 GB free (`app/files/service.py`).

### Migrations are backward compatible

- **Why:**
  - production migrates before it switches code;
  - a rollback runs older code on the newer schema.
- **Evidence:** [CLAUDE.md](../CLAUDE.md), "Schema changes"; [deployment.md](deployment.md).

### Backups hold no way into an account, and none of the NCERT data

- **Why:** a copy on disk must never let someone sign in; and the NCERT service owns its own backups.
- **Evidence:**
  - `deploy/backup.sh`: no rows from `auth_sessions`, `auth_verifications` or `file_chunks`, and no
    `ncert_knowledge` schema;
  - `1cdcb67` (2026-10-15; the owner's decision).
- **Cost:** after a restore, everyone signs in again, and files are read again.

## Production and operations

### One host, systemd, `main` as the source of truth (owner's rule)

- **Why:** simple and deterministic: the exact verified commit runs, and nothing else.
- **Evidence:**
  - [CLAUDE.md](../CLAUDE.md), "The owner's hard rules";
  - `173d8dc` (2026-09-28): "push main to production Git, rebuild and restart only what changed";
  - content keys in `deploy/server/lib.sh`;
  - PostgreSQL's container is the only one.
- **Cost:** no high availability and no staging ([INFRASTRUCTURE.md](../INFRASTRUCTURE.md), "Known limits").

### The jobs worker ships, but it isn't enabled

- **Why:** emails to students are an owner decision.
- **Evidence:** `JOBS_ENABLED=false` and `NOTIFICATIONS_MODE=off` by default; [deployment.md](deployment.md),
  "Jobs worker".
- **Cost:** in production, nothing sends reminder emails or forwards support requests by email, and two clean-up
  jobs don't run: the outbox redaction and the read-notification purge.

### No Docker on the development PC (owner's rule, 2026-09-29)

- **Why:** keep the owner's machine simple.
- **Evidence:** [CLAUDE.md](../CLAUDE.md), "The owner's hard rules".
- **Cost:** the backend tests, the end-to-end suite and `bun run verify` don't run there. CI runs them.
